# Clutch Court H-O-R-S-E (M4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Friends on a shared Clutch Court can play a casual game of H-O-R-S-E, with results saved to the DB.

**Architecture:**
- The rules are a pure reducer in `shared/court/horse.ts` (`reduce(state, event, now) → { state, effects }`), unit-tested with `node:test`.
- The Colyseus `CourtRoom`:
  - feeds it events (start, shot fired/landed, 250 ms ticks, disconnect/reconnect/leave);
  - mirrors its state into the synced schema;
  - executes its effects (broadcast, DB save, return to shootaround).
- The Angular court page renders the HUD from synced state, and the engine gets a shot gate and a floor ring.

**Tech Stack:** TypeScript, Colyseus 0.18 (`@colyseus/core`, `@colyseus/schema` `schema()`/`t.*`, `@colyseus/sdk`), Drizzle (Postgres), Three.js, Angular 20 signals, `node:test` via `tsx --test`.

**Spec:** `docs/superpowers/specs/2026-11-09-horse-design.md` (parent: `CLUTCH_COURT_SPEC.md` §6.5).

## Global Constraints

- Turn timer: **20 s** (`HORSE_TURN_MS = 20000`). Disconnect grace: **30 s** (`HORSE_DISCONNECT_MS = 30000`). Spot radius: **1.0 m** (`HORSE_SPOT_RADIUS = 1.0`). Winner screen / return to shootaround: **10 s** (`HORSE_RETURN_MS = 10000`).
- Letters: `"HORSE"`; 5 letters = eliminated. Set shots must be `insideThreePoint("A", x, z)` (half court, hoop A only).
- `shared/court/` stays pure: no Three.js, Colyseus, Angular or I/O imports. Relative imports there use `.js` extensions.
- Casual: no points, leaderboard or achievement hooks.
- Every new UI string is added to `frontend/src/app/core/i18n/court.ts` in **EN and EL** in the same task.
- Do not raise the DB pool or add polling; the only DB write is one transaction per finished game.
- Schema changes: none (tables `horse_games`, `horse_game_players` already exist in dev and prod).
- Commits end with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`. Work on branch `dev`.

## Review Focus

1. A second `horse:start` while a game is running (or from a non-starter) must be ignored, not restart the game. *Test in Task 1.*
2. A player who leaves while their shot is in the air: the pending `shotResult` must still advance the game and never stall it. *Test in Task 2.*
3. A `tick` while a shot is resolving must not time the turn out (the timer is paused). *Test in Task 2.*
4. Reconnecting after the 30 s elimination must not revive the player. *Test in Task 2.*
5. A 2-player game where one disconnects: their turns are skipped and after 30 s the other wins. The game must not deadlock while only one player is connected. *Test in Task 2.*

```ts
export const HORSE_TURN_MS = 20000;
export const HORSE_DISCONNECT_MS = 30000;
export const HORSE_SPOT_RADIUS = 1.0;
export const HORSE_RETURN_MS = 10000;
export const HORSE_WORD = "HORSE";

export type HorsePhase = "free" | "setting" | "matching" | "over";
export type ShotRejectReason = "notYourTurn" | "outsideArc" | "offSpot" | "busy";
export type HorseEventKind = "set" | "matched" | "letter" | "eliminated" | "winner" | "turn";

export interface HorsePlayer {
  id: string; letters: number; eliminated: boolean;
  eliminatedAt: number | null; disconnectedAt: number | null;
}
export interface HorseState {
  phase: HorsePhase;
  order: string[];                       // ids in join order, fixed at start
  players: Record<string, HorsePlayer>;  // only game participants
  setterId: string | null;
  turnId: string | null;
  spot: { x: number; z: number; hoop: HoopId } | null;
  matchQueue: string[];
  deadline: number | null;               // ms; null while resolving or not in a turn
  resolving: { playerId: string; remainingMs: number } | null;
  winnerId: string | null;
  startedAt: number | null;
  endedAt: number | null;
}
export interface HorseResult {
  winnerId: string | null; startedAt: number; endedAt: number;
  players: { id: string; letters: number; placement: number }[];
}
export type HorseInput =
  | { type: "start"; by: string; ownerId: string; players: { id: string; joinOrder: number; connected: boolean }[] }
  | { type: "shotFired"; playerId: string }
  | { type: "shotResult"; playerId: string; made: boolean; x: number; z: number }
  | { type: "tick" }
  | { type: "disconnect"; playerId: string }
  | { type: "reconnect"; playerId: string }
  | { type: "leave"; playerId: string };
export type HorseEffect =
  | { type: "event"; kind: HorseEventKind; playerId: string | null; letters?: string; remainingMs?: number }
  | { type: "save"; result: HorseResult }
  | { type: "returnToFree"; afterMs: number };

export function initialHorseState(): HorseState;              // phase "free", everything empty/null
export function lettersOf(n: number): string;                 // 0 -> "", 3 -> "HOR", 5 -> "HORSE"
export function canStart(players: { id: string; joinOrder: number; connected: boolean }[], ownerId: string, by: string): boolean;
export function shotGate(view: { phase: HorsePhase; turnId: string | null; spot: { x: number; z: number } | null; resolving: boolean },
                         playerId: string, x: number, z: number): ShotRejectReason | null;
export function reduce(state: HorseState, input: HorseInput, now: number): { state: HorseState; effects: HorseEffect[] };
```

Rules for `shotGate`:
- `free` or `over`: always `null`.
- Otherwise:
  - `resolving` → `"busy"`;
  - `playerId !== turnId` → `"notYourTurn"`;
  - `setting` and `!insideThreePoint("A", x, z)` → `"outsideArc"`;
  - `matching` and distance to spot `> HORSE_SPOT_RADIUS` → `"offSpot"`.
- `shotGate` is pure and shared by server and client.

`canStart`:
- At least 2 connected players.
- `by` is `ownerId` when the owner is connected; otherwise `by` must be the connected player with the lowest `joinOrder`.

`reduce` never mutates its input (return a new state object).

Every turn change emits `{ type: "event", kind: "turn", playerId: turnId, remainingMs: HORSE_TURN_MS }`.

### Task 2: Reducer timing: resolution delay, timeouts, disconnects, leaving, edge cases

**Files:**
- Modify: `shared/court/horse.ts`
- Modify: `shared/court/horse.test.ts`

**Interfaces:**
- Consumes/produces: the Task 1 API, unchanged. This task fills in the behaviour of `shotFired`, `tick`, `disconnect`, `reconnect` and `leave`.

Behaviour (spec rules 4–9):
- `shotFired` (valid only for `turnId`): `resolving = { playerId, remainingMs: deadline - now }`, `deadline = null`.
- `shotResult` (valid only when `resolving.playerId === playerId`): applies make/miss as in Task 1. Every shot result ends that turn: clear `resolving`, and give the next turn a fresh `deadline = now + HORSE_TURN_MS`. If the shooter has left meanwhile, still advance from their slot. (`resolving.remainingMs` exists only to pause the clock; it is never restored, because a resolved shot always ends the turn.)
- `tick`:
  - If `deadline !== null && now >= deadline`, treat it as a miss by `turnId`.
  - Eliminate any player with `now - disconnectedAt >= HORSE_DISCONNECT_MS` (setting `eliminatedAt = now`).
  - Then check for a winner.
- `disconnect`: sets `disconnectedAt = now`. If it's their turn and nothing is resolving, the turn is skipped immediately with no letter (setting: the setter role passes; matching: move to the next in the queue).
- `reconnect`: clears `disconnectedAt` unless already eliminated.
- `leave`: eliminate now (`eliminatedAt = now`), skip their turn if active, then check for a winner. In `free`, `leave` is a no-op.
- Winner check: at most one non-eliminated player → `over`. The winner is that player or `null`; emit `save` + `returnToFree`. An abandoned game (0 left) still emits `save` with `winnerId: null`.
